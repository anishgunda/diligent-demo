# Investigation architecture

FastAPI creates a scoped case and freezes the supplier baseline. The single-process worker loads the invoice and passes those records to a LangGraph state machine. The graph runs deterministic identity, sender and payment comparisons, then asks the configured provider to select optional tools. Tool calls execute against the bound case context, and the graph sends their structured outputs back to the provider before accepting its observations.

The Grok adapter uses the OpenAI-compatible Responses API. The default `grok-4.3` supports function calling and structured output, and the adapter specifies no reasoning effort for this model. Each run allows at most three decision turns and four optional tool calls, with one additional model call available for selected message analysis. Tools cannot choose an organisation, invoice ID or URL. Evidence distinguishes public observations, synthetic domains and unavailable sources. [Grok 4.3 capabilities](https://docs.x.ai/developers/models/grok-4.3) · [Responses API](https://docs.x.ai/developers/rest-api-reference/inference/responses)

The pure policy engine reads mandatory comparisons and independent verification. An agent observation has no authority to change the verdict, supplier baseline or payment approval. A missing or changed destination, unresolved identity discrepancy or absent trusted baseline keeps the invoice on hold. Independently confirmed fraud rejects the payment request. Legitimate verification can resolve the specific destination mismatch while preserving other holds.

When the provider fails or is absent, configured rules-only execution labels the skipped AI work. If fallback is disabled the case fails visibly. Tool events, evidence, immutable verification records and versioned audit reports persist in PostgreSQL. The browser can replay case events with a sequence cursor. The worker is single-instance and in-process. Live case access recovers jobs abandoned past their lease, and graceful shutdown marks interrupted jobs failed.
